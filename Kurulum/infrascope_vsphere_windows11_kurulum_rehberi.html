Kaynak planı

Küçük bir başlangıç kurulumu için mühendislik önerisi: 4 vCPU, 16 GB RAM ve 150 GB sanal disk. Bu değerler yük testiyle garantilenmiş cihaz kapasitesi değildir. Envanter, olay saklama süresi ve yedek büyümesine göre kaynaklar izlenip artırılmalıdır. Datastore ve Windows sistem diski için büyüme payı bırakın.

  1. Güncel ve Microsoft tarafından desteklenen Windows 11 Pro, Enterprise veya Education x64 ISO ve lisansını hazırlayın.
  2. vCenter yetkisi, Windows yerel yönetici yetkisi, uygun port group ve DNS/zaman erişimini sağlayın.
  3. WSL, Docker ve Windows güncellemeleri için gereken indirme erişimini planlayın. InfraScope lisans sunucusu: https://lisans.webmahsul.com.tr (TCP 443).
  4. Her müşteri için ayrı VM/kurulum, veritabanı ve benzersiz anahtarlar kullanın.
AMD ve destek koşulu

Broadcom, AMD için ESXi 7.0 U3o, 8.0 U1c veya sonraki uygun sürümleri belirtir. Docker, sanal makine ortamına yönelik resmi desteği Docker Business kapsamında sunar. Kurumun Docker abonelik ve destek koşullarını doğrulayın. Menü adları vSphere/Docker sürümüne göre değişebilir.

Kontrol noktası

ESXi / CPU bilgisi kaydedildi; kaynak, ISO, ağ ve lisans erişimi hazır.

02 / Anahtar sağlayıcısı ve vTPM

Windows 11 için vTPM 2.0 ve uygun firmware hazırlığı.

Ortamda uygun ve aktif bir anahtar sağlayıcısı zaten varsa yeni bir sağlayıcı oluşturmayın. Kurumun mevcut Native Key Provider veya KMS düzenini kullanın.

Native Key Provider, vSphere 7.0 U2 ve sonrasında bulunur. Bu adımlar vCenter yönetimi varsayar; bağımsız ESXi hostunda desteklenen vTPM/anahtar yönetimi yolunu vSphere yöneticisiyle netleştirin.

  1. vSphere Client içinde vCenter nesnesini seçin. Configure → Security → Key Providers bölümünü açın.
  2. Yeni kurulumda Add Native Key Provider seçin ve kurum standardına uygun bir ad verin.
  3. Yalnız TPM korumalı ESXi hostlarında kullanım seçeneğini fiziksel host özelliklerine göre belirleyin. Hostlarda TPM yoksa bu kısıtlama işaretli kalmamalıdır; değişikliği vSphere yöneticisiyle uygulayın.
  4. Back Up işlemini tamamlayın. İndirilen .p12 dosyasını ve varsa parolasını güvenli, bağımsız bir yerde saklayın. Sağlayıcının etkin/kullanılabilir olduğunu doğrulayın.
  5. VM oluştururken Add New Device → Trusted Platform Module ekleyin. VM Options → Boot Options altında EFI/UEFI ve Secure Boot ayarlarını doğrulayın.
Kurtarma için saklayın

Key Provider yedeği, InfraScope uygulama yedeğinden farklıdır. vTPM ve VM erişimini kurtarmak için de gerekir. Sağlayıcıyı silmeyin; vTPM aygıtını sonradan kaldırmayın. Windows disk şifrelemesi kullanılırsa ilgili kurtarma anahtarını ayrıca kurum kasasında saklayın.

vTPM eklenemiyorsa

“Key provider is not configured” veya “TPM2 device is required” hatasında sağlayıcı durumu, yedeği ve host uygunluğunu kontrol edin. TPM gereksinimi karşılanmadan Windows kurulumu aşamasına geçmeyin.

Resmi kaynak: [1], [11]

Kontrol noktası

Anahtar sağlayıcısı kullanılabilir, yedeği saklandı, VM için vTPM seçilebiliyor.

03 / Sanal makineyi oluşturun

İç içe sanallaştırma, VM kapalıyken etkinleştirilir.

  1. Create a new virtual machine sihirbazını başlatın. VM adı olarak örneğin IS-MUSTERI-01 kullanın; hedef cluster/host ve datastore seçin.
  2. Hedef hostlarla uyumlu güncel VM compatibility düzeyini seçin. Guest OS alanında Windows 11 (64-bit) kullanın. Seçenek görünmüyorsa vSphere sürümünü/uyumluluğu doğrulayın.
  3. Başlangıç kaynaklarını ayarlayın: 4 vCPU, 16 GB RAM, 150 GB disk. Thin disk kullanılıyorsa fiziksel datastore boşluğunu da izleyin.
  4. Kurum ağına ait port group seçin; ağ aygıtının başlangıçta bağlı olmasını sağlayın. VMXNET3 kullanılacaksa Windows sürücüsünü/VMware Tools medyasını hazırlayın.
  5. Windows ISO dosyasını sanal CD/DVD aygıtına bağlayıp açılışta bağlanmasını seçin. vTPM 2.0, EFI/UEFI ve Secure Boot ayarlarını kontrol edin.
  6. CPU → Hardware Virtualization altında Expose hardware assisted virtualization to the guest OS seçeneğini etkinleştirin. Ayarları kaydedin.
Ayarın amacı

Bu seçenek, Windows içindeki WSL2 motorunun sanallaştırma özelliklerine erişmesini sağlar. Sadece vCPU sayısını artırmak bu ayarı etkinleştirmez. Hyper-V için yazılmış Set-VMProcessor komutu vSphere yönetim komutu değildir.

vGPU veya PCI passthrough bu VM için gerekli değildir. Bu tür aygıtlarla nested virtualization çakışması varsa kurum yöneticisiyle VM donanımını uygun hale getirin; bağımlı başka iş yükünün aygıtını kaldırmayın.

Resmi kaynak: [3], [10]

Kontrol noktası

VM donanımı kaydedildi; nested virtualization, vTPM ve firmware ayarları doğrulandı.

04 / Windows 11 kurulumu

Kalıcı bir VM ve kurulumdan sonra kullanılacak tek işletim hesabı.

  1. VM konsolunu açın, ISO ile başlatın ve Windows 11 kurulumunu tamamlayın. Doğru disk, dil ve saat dilimini seçin.
  2. Ağ aygıtı veya disk görünmüyorsa seçilen sanal donanımın Windows sürücüsünü yükleyin; ardından kurulum sihirbazına dönün.
  3. Kurumun hesap/etki alanı politikasına uygun işletim hesabıyla oturum açın. Docker Desktop daha sonra aynı kullanıcı profili altında kullanılmalıdır.
  4. vSphere içinden VMware Tools kurulum medyasını bağlayın, kurulumu tamamlayın ve gerekiyorsa yeniden başlatın.
  5. Windows Update işlemlerini ve yeniden başlatmaları tamamlayın. Sanal makinenin IP, DNS, ağ geçidi ve saat eşitlemesini doğrulayın.
  6. Ayarlar → Sistem → Güç bölümünde elektriğe bağlı kullanımda otomatik uyku/hibernasyon olmayacak şekilde kurum politikasını uygulayın.

Windows içinden kontrol

hostname
ipconfig /all
wsl --version

WSL henüz yüklü değilse son komutun hata vermesi bu aşamada normaldir; bir sonraki adımda kurulacak. Windows sürümünü winver ile kontrol edin.

Yerel erişim ne demektir?

http://localhost:8170 adresi, tarayıcının çalıştığı Windows VM’ini ifade eder. Kendi bilgisayarınızın tarayıcısında aynı adresi açmak VM’e bağlanmaz. Yerel kullanımda VM konsolundan veya kurumun yetkilendirdiği uzak masaüstü oturumundan VM içindeki tarayıcıyı açın.

Kontrol noktası

Windows güncel, Tools hazır, ağ/saat doğru ve işletim hesabı belirlendi.

05 / WSL2 bileşenini kurun

Komutlar Windows PowerShell içinde uygulanır.

Yönetici olarak PowerShell açın. Yeni bir Windows kurulumunda aşağıdaki komut WSL bileşenlerini hazırlar; ayrıca Ubuntu kurmanız gerekmez.

wsl --install --no-distribution

Windows yeniden başlatma istiyorsa çalışmaları kaydedip VM’i yeniden başlatın. Aynı işletim hesabıyla tekrar oturum açın. Ardından yönetici PowerShell içinde devam edin:

wsl --update
wsl --set-default-version 2
wsl --version
wsl --status

Güncel WSL sürümünü kullanın; Docker belgesindeki alt sınır 2.1.5’tir. “Varsayılan sürüm 2” ile WSL yazılımının 2.x sürüm numarası farklı bilgilerdir. Docker Desktop kendi Linux ortamını oluşturur; ayrıca bir Linux dağıtımına Docker Engine kurmayın.

WSL bileşeni etkin mi?

Get-WindowsOptionalFeature -Online -FeatureName VirtualMachinePlatform

Çıktıda State: Enabled beklenir. Komutlar desteklenmiyorsa Windows güncellemelerini tamamlayın ve resmi WSL kurulum/hata giderme adımlarını izleyin. Nested virtualization hatasında 03. adımdaki VM CPU ayarına dönün.

Devam koşulu

WSL komutlarında sanal makine başlatma/sanallaştırma hatası kalmamalıdır. Gereken Windows yeniden başlatmasını atlamayın. Üretim kurulumu sırasında wsl --shutdown çalıştırmak Docker iş yüklerini de durdurur.

Resmi kaynak: [6], [7], [9]

Kontrol noktası

WSL güncel, varsayılan sürüm 2, VirtualMachinePlatform etkin.

06 / Docker Desktop kurulumu

Windows x64 kurucusu, WSL2 motoru ve Linux containers.

  1. Docker’ın resmi Windows indirme sayfasından x86_64/AMD64 Docker Desktop kurucusunu indirin. ARM64 paketi bu InfraScope teslimi için uygun değildir.
  2. Kurucuyu çalıştırın. WSL2 motoru seçeneği görünüyorsa etkinleştirin; istenen yetki ve yeniden başlatma adımlarını tamamlayın.
  3. Windows işletim hesabıyla oturum açıp Docker Desktop’ı elle başlatın. Kurumun abonelik koşullarını değerlendirdikten sonra lisans sözleşmesini yetkili kişi kabul etmelidir.
  4. Settings → General altında Use WSL 2 based engine ayarını doğrulayın. Uyumlu sistemde varsayılan açık olduğundan seçenek görünmeyebilir.
  5. Docker Windows containers modundaysa menüden Linux containers moduna geçin. Docker motorunun Running durumuna gelmesini bekleyin.
  6. Start Docker Desktop when you sign in ayarını etkinleştirin. Windows’ta başka bir hesapla giriş yapmak aynı WSL/Docker verilerini kullanacağı anlamına gelmez.

Windows PowerShell içinde doğrulayın

docker version
docker compose version
docker info --format '{{.OSType}}/{{.Architecture}}'
docker context show

docker version hem Client hem Server bilgisi vermelidir. Platform çıktısı linux/x86_64 veya linux/amd64 olmalıdır. Server’a bağlanamıyorsanız InfraScope kurucusuna geçmeyin. Bağlamın uzaktaki başka bir Docker sunucusuna yönelmediğini doğrulayın.

Resmi kaynak: [4], [7], [8]

Kontrol noktası

Yerel Linux Docker motoru ve Compose çalışıyor.

07A / İnternetten kurulum

Büyük imaj ZIP’i taşımadan küçük kurulum dosyasıyla başlayın.

InfraScope Releases sayfasından install-infrascope.ps1 ve SHA256SUMS-online dosyalarını alın. Code → Download ZIP yalnız kaynak koddur. Betiği güvenilir release hash’iyle karşılaştırın. Aşağıda 1.0.2 örnektir; yalnız gerçekten yayımlanmış sürümü seçin. Bu kılavuz uzak yayın yapıldığını göstermez.

Get-FileHash .\install-infrascope.ps1 -Algorithm SHA256
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\install-infrascope.ps1 -Version 1.0.2 `
  -Destination C:\InfraScope\infrascope `
  -ProjectName infrascope-musteri

Hedef klasör boş olmalıdır. Başlatıcı release ZIP’inin GitHub SHA-256 değerini, paket dosyalarını ve sürümü doğrular. App, NMS ve PostgreSQL imajları sabit digest referanslarıyla indirilir. Sonra 09. adımdaki lisans/ilk yönetici adımına geçin; 07B ve 08 çevrimdışı alternatifidir.

Özel depo / imaj

Özel release erişimi için GH_TOKEN yalnız o PowerShell oturumunda ayarlanır. Özel GHCR imajları için aynı Windows kullanıcısıyla docker login ghcr.io gerekir. Tokenı .env veya betiğe yazmayın; ayrıntılar INSTALL_WINDOWS.md içindedir. Açık paketlerde giriş gerekmez.

GitHub API/release indirme alanları, GHCR ve Docker Hub HTTPS erişimi gerekir. Kurulum başladıktan sonra hata olursa kalıcı klasörde install.ps1 ile devam edin; başlatıcı mevcut kurulumun üzerine yazmaz.

Kontrol noktası

Doğru yayımlanmış sürüm seçildi; hash ve imaj erişimleri doğrulandı.

07B / Çevrimdışı paketi açın

Alternatif yol: mevcut InfraScope 1.0.1 müşteri ZIP’i.

Müşteri ZIP’ini ve güvenilir kanaldan alınmış SHA256SUMS-1.0.1.txt dosyasını VM’de örneğin C:\Install klasörüne kopyalayın. Windows PowerShell içinde:

certutil -hashfile C:\Install\infrascope-customer-deploy-1.0.1.zip SHA256

Beklenen 1.0.1 ZIP SHA-256 değeri:

acbc516717ce13d7e99fbcec88befece28c656e629e96e5f5323527c0d043786

Değeri karakter karakter teslim manifestiyle karşılaştırın. Fark varsa dosyayı tekrar güvenilir kaynaktan alın; devam etmeyin. Hash eşleşmesi dosya bütünlüğünü gösterir; kaynağın kimliğini ayrıca güvenilir teslim kanalı belirler.

Yeni kurulum klasörü

Expand-Archive `
  -LiteralPath C:\Install\infrascope-customer-deploy-1.0.1.zip `
  -DestinationPath C:\InfraScope
Set-Location C:\InfraScope\infrascope
Get-ChildItem

Beklenen dosyalar: install.ps1, backup.ps1, docker-compose.yml, env.example, INSTALL_WINDOWS.md ve images klasörü. images içinde uygulama, NMS ve PostgreSQL arşivleri ile image-manifest.json bulunur.

Kalıcı konum

ZIP içinde infrascope üst klasörü vardır; yukarıdaki komutlarla çalışma yolu C:\InfraScope\infrascope olur. OneDrive/geçici klasör kullanmayın. Mevcut kurulumun üzerine Expand-Archive -Force uygulamayın; güncelleme prosedürünü izleyin.

Kontrol noktası

ZIP hash’i eşleşti, dosyalar kalıcı klasöre açıldı, üç imaj arşivi mevcut.

08 / Servisleri kurun

Normal PowerShell; gerektiğinde Windows’un yetki isteğini değerlendirin.

Set-Location C:\InfraScope\infrascope
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\install.ps1 -ProjectName infrascope-musteri

ExecutionPolicy Bypass yalnız bu PowerShell çalıştırması için kullanılır. Kurumun AppLocker/WDAC gibi uygulama politikalarını değiştirmez. Betik kısıtlanırsa kurumun onaylı imzalama/çalıştırma yöntemini kullanın.

Kurucu adımıOluşan durum
YapılandırmaBoş şablondan .env; benzersiz DB/oturum/şifreleme/NMS anahtarları
İmaj hazırlığıPaket arşivlerinin hash ve imaj kimliği doğrulaması, Docker’a yükleme
VeritabanıPostgreSQL volume ve bekleyen şema migration işlemleri
Uygulama / NMS / yedekapp, nms, postgres, database-backup servisleri
Son kontrolServislerin hazır/healthy olmasının beklenmesi

İşlem bitene kadar terminali kapatmayın. Kurucu imajları paketten yükler; bu aşama registry hesabı gerektirmez. Docker/WSL kurulumu ve gerçek lisans etkinleştirmesi ayrıca ağ erişimi ister.

8170 portu kullanımdaysa

powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\install.ps1 -ProjectName infrascope-musteri -AppPort 8171

Bu seçenekle uygulama adresi http://localhost:8171 olur; sonraki sağlık kontrolünde de bu portu kullanın. ProjectName ve kurulum yolu ilk kurulumdan sonra sabit kalmalıdır. Mevcut .env anahtarlarını elle yenilemeyin.

Kontrol noktası

Kurucu hata vermeden tamamlandı; terminalde kurulum adresi gösterildi.

09 / Lisans ve ilk yönetici

Sihirbazı Windows VM’in tarayıcısında tamamlayın.

  1. Windows VM içinde Edge/Chrome açıp http://localhost:8170/setup adresine gidin. Farklı port seçtiyseniz o portu kullanın.
  2. Müşteriye verilmiş lisans anahtarını girip Lisansı Aktive Et düğmesine basın. Hata varsa DNS, saat, proxy/sertifika ve lisans sunucusu erişimini düzeltin.
  3. Kurum adını, ilk yönetici adını, e-posta adresini ve güçlü parolayı girin. İlk Admini Oluştur düğmesini kullanın.
  4. Kurulum tamamlandı mesajından sonra Login Ekranına Git seçeneğiyle giriş yapın. Varsayılan yönetici hesabı/parolası yoktur.
  5. Olay Merkezi ve Ağ Topolojisi sayfalarını açın; yükleme tamamlandıktan sonra sayfa içeriğini doğrulayın. Boş müşteri kurulumunda cihaz ve incident olmaması normaldir.

Hazırlık ve kurulum durumunu doğrulayın

Invoke-RestMethod http://localhost:8170/api/health/ready
Invoke-RestMethod http://localhost:8170/api/setup/status

İlk yanıtta status: ready, version: 1.0.1 ve app/database için ready beklenir. İkinci yanıtta yönetici oluşturulduktan sonra hasAdmin: true ve setupRequired: false beklenir.

Hazır olmak ile entegrasyon sağlığı farklıdır

Readiness, uygulama ve veritabanı erişimini kontrol eder. VMware/Fortinet/Zabbix/NMS/e-posta tanımlanmadan entegrasyon uyarıları olabilir. Bu, tek başına veritabanı kurulumunun başarısız olduğu anlamına gelmez. Varsayılan sistem alarm kataloğu, müşteri olayı değildir.

Kontrol noktası

Gerçek müşteri lisansı kabul edildi, ilk yönetici giriş yaptı, sayfalar yüklendi.

10 / Entegrasyon ve kabul

Önce servisleri, sonra her gerçek veri kaynağını doğrulayın.

Set-Location C:\InfraScope\infrascope
docker compose ps
docker compose logs --tail 100 app nms database-backup

Dört servis için Up/healthy durumunu doğrulayın. Kurucu 300 saniyede zaman aşımına uğrarsa günlükleri inceleyin; terminalde başarısız kurulum varken hizmeti kabul etmeyin. Günlükler kuruma özel bilgi içerebilir; destekle paylaşmadan önce maskeleyin.

İşlevMüşteride yapılacak doğrulama

SNMP / SSH izlemeVM’den ve Docker içinden hedefe yönlendirme/ACL; gerçek cihaz test isteği
E-postaSMTP ayarları ve yetkili adrese kontrollü test iletisi

vSphere port group, Windows güvenlik duvarı, yönlendirici ACL ve cihaz erişim listelerini birlikte değerlendirin. Windows içindeki bir TCP bağlantı testi, konteynerin eriştiğini tek başına kanıtlamaz. SNMP için TCP testi kullanmayın; uygulamanın gerçek protokol testini kullanın.

Yerel web erişimi

PostgreSQL 5432 ve NMS 8500 dışarı açılmamalıdır. Mevcut Compose web portunu host arayüzlerinde yayınlayabilir; Windows güvenlik duvarında 8170’i LAN’a açmayın. Başka bilgisayarlardan web erişimi gerekiyorsa alan adı, HTTPS ve uygulama URL’si ayrıca yapılandırılmalıdır.

Kontrol noktası

Dört servis healthy; tanımlanan her entegrasyon gerçek müşteri ortamında doğrulandı.

11 / Yeniden başlatma provası

Docker Desktop’ın Windows kullanıcı oturumuna bağlı başlangıcını doğrulayın.

  1. İlk taşınabilir yedeği alın (12. adım). Kullanıcıdan planlı kesinti için uygun zamanı belirleyin.
  2. Windows’u normal biçimde yeniden başlatın. Aynı işletim hesabıyla tekrar oturum açın.
  3. Docker Desktop’ın açıldığını ve motorun Running durumuna geldiğini doğrulayın.
  4. Kurulum klasöründe docker compose ps ve readiness kontrolünü çalıştırın. Gerekirse aşağıdaki kontrollü başlatmayı uygulayın.
  5. Yöneticiyle tekrar giriş yapın; kurum, kullanıcılar ve lisans durumunun korunduğunu doğrulayın.
  6. Bir cihaz entegrasyonu varsa yeni ölçümün/alım zamanının ilerlediğini kontrol edin. Sonucu teslim kontrol listesine işleyin.

Yeniden başlatma sonrası işletim hesabıyla giriş ve doğrulama sürecini kurumla belirleyin. Uyku, oturum profili silinmesi, Docker’ın kapanması veya disk dolması izlemeyi keser.

12 / Şifreli taşınabilir yedek

Veritabanı ile birlikte kurulum anahtarlarını koruyun.

  1. C:\Private gibi yalnız yetkili işletim hesabının eriştiği bir yerde, en az 16 baytlık tek satırdan oluşan güçlü kurtarma parolası dosyası hazırlayın. Metin düzenleyicide UTF-8 olarak saklayın.
  2. Dosyanın Windows izinlerini kontrol edin. Örnek dosya adı: infrascope-recovery-passphrase.txt. Parolayı komut satırına veya bu belgeye yazmayın.
  3. Kurulum klasöründen aşağıdaki yedek komutunu çalıştırın.
  4. backups altında oluşan .isbackup dosyasını farklı disk/sunucu/depolamaya kopyalayın. Kurtarma parolasını yedekten ayrı güvenli kasada saklayın.
  5. İlk teslimde ve önemli sürüm değişimlerinde ayrı bir test ortamında geri yükleme doğrulaması yapın. Canlı veritabanını prova için sıfırlamayın.
Set-Location C:\InfraScope\infrascope
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\backup.ps1 `
  -PassphraseFile C:\Private\infrascope-recovery-passphrase.txt
Get-ChildItem .\backups -Filter *.isbackup

Kontrol noktası

İlk .isbackup oluşturuldu, bağımsız hedefe kopyalandı, parola ayrı saklandı.

12A / Yedek alarak güncelleyin

Aynı kurulum yolu, aynı Docker projesi ve korunmuş müşteri ayarları.

Yeni sürümün release notlarını okuyun. Bakım penceresinde kullanıcı/entegrasyon yazmalarını durdurun. Docker Desktop çalışır durumda olsun. VERSION değerini elle değiştirmeyin. 1.0.2 örnek sürümdür.

Tüm servisler healthy; müşteri verileri/ayarları doğru; yedek ve parola ayrı saklandı.
