1. Kurulum Modeli

InfraScope müşteri ortamına on-premise Docker kurulumu olarak kurulur. Bu modelde uygulama ve PostgreSQL veritabanı müşteri sunucusunda çalışır. Müşteri verisi müşteri ortamında kalır.

Lisans aktivasyonu ve lisans doğrulama işlemleri InfraScope merkezi lisans servisi üzerinden yapılır:

https://lisans.webmahsul.com.tr
Önemli: Merkezi lisans sunucusu müşteriye kurulmaz. Müşteri paketinde deploy/license-server/, DEPLOYMENT_MODE=license-server veya LICENSE_SERVER_MODE=true bulunmamalıdır.

Müşteri tarafında çalışan servisler

  • postgres: InfraScope veritabanı.
  • app: InfraScope web uygulaması ve API.
  • Opsiyonel entegrasyonlar: VMware, FortiGate, FortiAnalyzer, NMS ve SNMP yapılandırmaları.

Paket içinde bulunmaması gerekenler:

  • LICENSE_SERVER_MODE=true veya DEPLOYMENT_MODE=license-server ayarları

4. Dosyaları ve Image'ı Alma

InfraScope kurulumu iki parçadan oluşur: küçük kurulum paketi ve Docker image. Kurulum paketi müşteriye güvenli bağlantı, dosya transferi veya destek ekibi tarafından sağlanır. Uygulama image'ı ise normalde registry üzerinden çekilir.

4.1 Standart online kurulum

Müşteriye verilen paket örnek olarak şu isimde olabilir:

infrascope-customer-install-1.0.0.zip

Sunucuda paketi açın:

mkdir infrascope
cd infrascope
unzip /path/to/infrascope-customer-install-1.0.0.zip

Image bilgisi .env.example içinde pinli gelir:

REGISTRY=ghcr.io/celebigilfatih
VERSION=1.0.0

./install.sh çalışırken aşağıdaki image'ı çeker:

ghcr.io/celebigilfatih/infrascope:1.0.0

4.2 Git üzerinden kurulum paketini alma

Kurulum paketi Git üzerinden de alınabilir. Bunun için müşteriye ana uygulama kaynak kodu reposu değil, yalnızca müşteri kurulum dosyalarını içeren ayrı bir private installer repo verilmelidir.

Önerilen repo içeriği:

docker-compose.yml
.env.example
install.sh
update.sh
INSTALL.md
infrascope_customer_cookbook.html

Örnek Git akışı:

git clone --branch v1.0.0 https://github.com/celebigilfatih/infrascope-customer-install.git infrascope
cd infrascope
cp .env.example .env
chmod +x install.sh update.sh
./install.sh
Müşteriye celebigilfatih/infrascope ana kaynak kod reposunu vermeyin. Ana repo lisans sunucusu dosyaları, geliştirme scriptleri, internal dokümantasyon veya müşteriye ait olmayan operasyonel parçalar içerebilir.

Git ile alınan kurulum dosyaları sadece compose ve scriptleri getirir. Uygulama yine Docker image olarak REGISTRY ve VERSION değerlerine göre çekilir.

4.3 Private registry erişimi gerekiyorsa

Registry private ise InfraScope size kullanıcı adı ve read:packages yetkili access token sağlar. Kurulumdan önce login olun:

docker login ghcr.io

Ardından image erişimini test edin:

docker pull ghcr.io/celebigilfatih/infrascope:1.0.0
Access token, lisans key ve .env değerleri gizlidir. Bunları ticket, e-posta veya ekran görüntüsünde paylaşmayın. Token sadece image pull ve gerekirse installer repo okuma yetkisine sahip olmalıdır.

4.4 Kısıtlı ağ / offline image aktarımı

Sunucunun registry erişimi yoksa InfraScope destek ekibi aynı tag ile hazırlanmış image arşivi sağlayabilir:

infrascope-image-1.0.0.tar

Image'ı sunucuya kopyalayıp yükleyin:

docker load -i infrascope-image-1.0.0.tar
docker images | grep infrascope

Arşiv içindeki image tag'i .env dosyasındaki REGISTRY ve VERSION ile aynı olmalıdır. Örnek:

ghcr.io/celebigilfatih/infrascope:1.0.0
İlk lisans aktivasyonu için sunucunun https://lisans.webmahsul.com.tr adresine erişebilmesi gerekir. Tamamen kapalı ağ senaryoları için kurulumdan önce InfraScope destek ekibiyle ayrıca planlama yapılmalıdır.

5. Windows Server Üzerinde Git ile Kurulum

InfraScope mevcut haliyle Linux container olarak çalışır. Bu nedenle Windows Server üzerinde doğrudan Windows container olarak çalıştırılmaz. Windows Server kullanılacaksa önerilen model, Windows Server üzerinde küçük bir Ubuntu VM veya WSL2 Ubuntu ortamı çalıştırmak ve kurulumu bu Linux ortamı içinde yapmaktır.

Production için en anlaşılır ve izole model Ubuntu VM kullanmaktır. WSL2 daha hızlı kurulur, ancak production operasyonlarında VM kadar net izolasyon ve yönetim sınırı sunmayabilir.

5.1 Önerilen model: Ubuntu VM

  1. Windows Server üzerinde Hyper-V, VMware veya kurumunuzun kullandığı sanallaştırma katmanında Ubuntu Server VM oluşturun.
  2. VM'e sabit IP verin veya DNS kaydı tanımlayın.
  3. Windows firewall ve ağ kurallarında seçilen uygulama portunu açın. Önerilen port: 8170.
  4. Ubuntu içinde Docker Engine, Docker Compose v2 ve Git kurun.
  5. Kurulum komutlarını Ubuntu shell içinde çalıştırın.

Ubuntu içinde temel kontrol komutları:

git --version
docker --version
docker compose version
docker info
curl -I https://lisans.webmahsul.com.tr

5.2 Alternatif model: WSL2 Ubuntu

WSL2 Ubuntu kullanılacaksa Docker ve Git komutları Windows PowerShell yerine WSL Ubuntu shell içinde çalıştırılmalıdır. Kurulum klasörü Linux dosya sistemi altında tutulmalıdır.

cd ~
mkdir infrascope
cd infrascope
WSL2 modelinde port yönlendirme ve servis sürekliliği kurum politikasına göre ayrıca kontrol edilmelidir. Demo ve POC için pratik olabilir; uzun süreli production için Ubuntu VM tercih edilir.

5.3 Private installer repo clone

Müşteriye ana kaynak kod reposu yerine yalnızca kurulum dosyalarını içeren private installer repo erişimi verilir:

git clone --branch v1.0.0 https://github.com/celebigilfatih/infrascope-customer-install.git infrascope
cd infrascope

Private repo erişimi için read-only deploy key veya fine-grained GitHub token kullanılmalıdır. Token yalnızca installer repo erişimine sahip olmalıdır. GHCR private image için ayrıca read:packages yetkisi gerekir.

5.4 Kurulum

cp .env.example .env
chmod +x install.sh update.sh
./install.sh

Script çalışırken lisans key, uygulama URL'i ve port sorulur. Windows Server üzerindeki Ubuntu VM için uygulama URL'i genellikle şu şekilde olur:

http://WINDOWS_SERVER_IP:8170

5.5 Image kaynağı

Git sadece kurulum dosyalarını indirir. Uygulama kaynak koddan build edilmez; Docker image registry'den pinli sürümle çekilir:

REGISTRY=ghcr.io/celebigilfatih
VERSION=1.0.0

Private registry gerekiyorsa Ubuntu shell içinde login olun:

docker login ghcr.io
docker pull ghcr.io/celebigilfatih/infrascope:1.0.0

5.6 Windows Server dış erişim kontrolü

Kurulumdan sonra Windows Server veya VM ağ katmanında seçilen portun açık olduğundan emin olun. Tarayıcıdan şu adres açılmalıdır:

http://WINDOWS_SERVER_IP:8170/setup
Kaynak kod paylaşımı yapmayın: celebigilfatih/infrascope ana repo müşteriye verilmemelidir. Müşteri sadece installer repo, lisans key ve gerekiyorsa registry erişimi almalıdır.

6. Sunucu Ön Kontrolü

Kuruluma başlamadan önce müşteri sunucusunda aşağıdaki komutları çalıştırın:

docker --version
docker compose version
docker info
curl -I https://lisans.webmahsul.com.tr

Önerilen portun boş olduğunu kontrol edin:

ss -ltnp | grep ':8170' || true

Beklenen durum:

  • Docker komutları hata vermeden çalışır.
  • docker info Docker daemon'a bağlanır.
  • lisans.webmahsul.com.tr için HTTP response alınır.
  • 8170 portu başka bir servis tarafından kullanılmıyordur.

7. Adım Adım Kurulum

7.1 Kurulum klasörü oluşturma

mkdir infrascope
cd infrascope

7.2 Paket dosyalarını kopyalama

Size verilen kurulum paketindeki dosyaları bu klasöre kopyalayın. Sonra dosyaları kontrol edin:

ls -la

7.3 Ortam dosyasını hazırlama

cp .env.example .env

.env dosyasında temel değerler kurulum scripti tarafından düzenlenir. Manuel kontrol etmek isterseniz:

nano .env

Temel lisans ayarları şu şekilde olmalıdır:

LICENSE_SERVER_URL=https://lisans.webmahsul.com.tr
LICENSE_KEY=IS-2026-XXXX-XXXX-XXXX

7.4 Script yetkileri

chmod +x install.sh update.sh

7.5 Kurulumu başlatma

./install.sh

Script sizden aşağıdaki bilgileri ister:

SoruÖrnek DeğerAçıklama
License keyIS-2026-XXXX-XXXX-XXXXInfraScope tarafından size verilen lisans key.
Application URLhttp://SUNUCU_IP:8170Kullanıcıların tarayıcıdan erişeceği adres.
Host port8170Sunucu üzerinde dışarı açılacak port.

Script otomatik olarak şunları üretir ve hazırlar:

  • NEXTAUTH_SECRET: oturum güvenliği için gizli anahtar.
  • POSTGRES_PASSWORD: PostgreSQL şifresi.
  • data/machine-id: lisans aktivasyonu için kalıcı makine kimliği.
  • data/license-cache: offline grace süresi için yerel lisans cache'i.
  • logs ve certs klasörleri.
Güvenlik notu: .env dosyası şifre ve lisans bilgisi içerir. E-posta, ticket, ekran görüntüsü veya ortak paylaşım alanlarında paylaşmayın.

8. İlk Açılış ve Admin Oluşturma

Kurulum tamamlandıktan sonra tarayıcıdan setup ekranını açın:

http://SUNUCU_IP:8170/setup

Farklı port seçtiyseniz URL'de kendi portunuzu kullanın:

http://SUNUCU_IP:APP_PORT/setup

Setup wizard adımları

  1. Lisans aktivasyonu yapılır.
  2. Firma / organizasyon adı girilir.
  3. İlk admin kullanıcısı oluşturulur.
  4. Login ekranına yönlendirilir.
Default admin yoktur. İlk admin hesabı müşteri tarafından setup wizard içinde oluşturulur. Şifreyi InfraScope ekibi belirlemez ve saklamaz.

İlk login

Setup tamamlandıktan sonra oluşturduğunuz admin e-posta ve şifresiyle giriş yapın:

http://SUNUCU_IP:8170/login

9. Kurulumu Doğrulama

Container durumunu kontrol edin:

docker compose ps

Uygulama ve veritabanı readiness kontrolü:

curl -sf http://localhost:8170/api/health/ready

Uygulama loglarını izlemek için:

docker compose logs -f app

Beklenen durum:

  • postgres servisi çalışıyor ve healthy durumdadır.
  • app servisi çalışıyor ve healthy durumdadır.
  • /api/health/ready hata vermeden yanıt döner.
  • Tarayıcıdan login ekranı açılır.
  • Admin ile giriş sonrası dashboard açılır.
/api/health veya /api/health/alarms, entegrasyonlar henüz yapılandırılmadıysa degraded dönebilir. Docker readiness için temel kontrol /api/health/ready endpoint'idir.

10. Lisans Durumu

Uygulamaya admin olarak giriş yaptıktan sonra lisans durumunu şu ekrandan kontrol edin:

Settings → License

Bu ekranda aşağıdaki bilgileri görebilirsiniz:

  • Lisans durumu: active, grace veya restricted.
  • Plan / tier bilgisi.
  • Cihaz ve kullanıcı limitleri.
  • Geçerlilik tarihi ve kalan gün sayısı.
  • Makine kimliği ve son doğrulama zamanı.

Lisans doğrulama mantığı

  • İlk kurulumda lisans merkezi sunucudan aktive edilir.
  • Uygulama düzenli olarak lisansı doğrular ve heartbeat gönderir.
  • Lisans sunucusuna geçici erişim yoksa yerel cache ile grace süresi kullanılabilir.
  • Lisans iptal edilirse, askıya alınırsa veya süresi dolarsa ilgili kısıtlamalar uygulanır.

11. Self-Signed Sertifikalar

FortiAnalyzer, FortiGate veya vCenter private/self-signed sertifika kullanıyorsa TLS doğrulamasını kapatmayın. Bunun yerine ilgili CA sertifikasını ./certs klasörüne koyun.

Örnek dosya yerleşimi:

certs/fortianalyzer-ca.pem
certs/fortigate-ca.pem
certs/vmware-ca.pem

.env içine gerekli path değerlerini girin:

FORTIANALYZER_TLS_CA_CERT_PATH=/app/certs/fortianalyzer-ca.pem
FORTIGATE_TLS_CA_CERT_PATH=/app/certs/fortigate-ca.pem
VMWARE_TLS_CA_CERT_PATH=/app/certs/vmware-ca.pem
Production ortamında NODE_TLS_REJECT_UNAUTHORIZED=0 kullanmayın. Bu ayar TLS doğrulamasını global olarak kapatır ve container production modda başlatılmamalıdır.

Sertifika değişikliği sonrası uygulamayı yeniden başlatın:

docker compose restart app

12. Güncelleme

Production kurulumlarda sürüm pinli olmalıdır. Size bildirilen sürüm numarasını kullanın; latest tercih edilmez.

Önerilen güncelleme komutu

./update.sh 1.0.1

Bu komut:

  • Veritabanı yedeği alır.
  • Yeni image sürümünü indirir.
  • Gerekli migration işlemlerini çalıştırır.
  • Servisleri yeniden başlatır.
  • Readiness kontrolü yapar.

Güncel sürümü .env içinde de kontrol edebilirsiniz:

grep '^VERSION=' .env
./update.sh komutunu sürüm argümanı olmadan çalıştırmak latest hedefini kullanabilir. Müşteri production ortamlarında her zaman size bildirilen pinli sürümü kullanın.

14. Sorun Giderme

Docker çalışmıyor

docker info

Hata alırsanız Docker daemon çalışmıyor olabilir. Docker servisini başlatıp kurulumu tekrar deneyin.

Port dolu

ss -ltnp | grep ':8170' || true

Port doluysa install.sh çalışırken farklı bir port seçin veya .env içinde APP_PORT değerini değiştirip servisleri yeniden başlatın.

Lisans sunucusuna erişilemiyor

curl -I https://lisans.webmahsul.com.tr

Firewall, proxy, DNS veya outbound internet kısıtlarını kontrol edin. İlk aktivasyon için merkezi lisans sunucusuna erişim gerekir.

Activation limit dolu

Aynı lisans farklı bir sunucuda daha önce aktive edilmiş olabilir. InfraScope destek ekibi eski activation kaydını deaktive ettikten sonra yeni sunucuda tekrar aktivasyon yapılabilir.

App healthy olmuyor

docker compose ps
docker compose logs -f app
docker compose logs -f postgres

En yaygın nedenler eksik NEXTAUTH_SECRET, eksik POSTGRES_PASSWORD, yanlış DATABASE_URL, image erişim hatası veya migration hatasıdır.

Setup ekranı tekrar açılmıyor

En az bir admin kullanıcı oluşturulduktan sonra setup ekranı kapanır. Devam etmek için login ekranını kullanın:

http://SUNUCU_IP:8170/login

Admin şifresi unutuldu

Kurulumda default admin yoktur ve şifre InfraScope tarafından bilinmez. Şifre sıfırlama veya kullanıcı kurtarma süreci için kurum içi prosedürünüzü ve InfraScope destek kanalını kullanın.

15. Destek İçin Gerekli Bilgiler
