Bu doküman, InfraScope kurulduktan ve ilk admin hesabı oluşturulduktan sonra müşteri IT ekibinin uygulamayı günlük operasyonda nasıl kullanacağını anlatır. Kurulum adımları için ayrı infrascope_customer_cookbook.html dosyasını kullanın.

1. Kapsam ve Roller

InfraScope, müşteri ortamındaki fiziksel altyapı, network cihazları, firewall görünümü, VMware envanteri, alarm üretimi ve temel güvenlik gözlemi için kullanılan operasyon panelidir. Müşteri verisi kendi kurulumundaki PostgreSQL veritabanında kalır. Lisans doğrulaması merkezi lisans sunucusuna yapılır.

Rol Tipik kullanım Dikkat edilmesi gerekenler
Admin Kullanıcı, lisans, entegrasyon, alarm ve sistem ayarlarını yönetir. Entegrasyon şifreleri ve API key bilgileri sadece yetkili kişilerle paylaşılmalıdır.
Network ekibi Switch, firewall, VPN, topology ve config backup ekranlarını kullanır. Silme ve değiştirme işlemlerinde audit log oluşur.
Sistem ekibi VMware cluster, host, VM, datastore ve snapshot ekranlarını izler. vCenter erişimi kesilirse ilgili veriler güncellenmez.
SecOps Riskli firewall kuralları, VIP, SSL-VPN, quarantine ve güvenlik alarmlarını inceler. InfraScope tespit ve görünürlük sağlar; cihaz üzerindeki değişiklikler kontrollü yapılmalıdır.
Önemli: Merkezi lisans yönetim paneli müşteriye kurulmaz. Müşteri ortamında /license-admin menüsü görünmemelidir. Müşteri tarafında lisans durumu Settings > License ekranından izlenir.

2. İlk Giriş

  1. Tarayıcıdan uygulama adresini açın: http://SUNUCU_IP:8170.
  2. İlk kurulum tamamlandıysa sistem sizi /login ekranına yönlendirir.
  3. İlk admin hesabı kurulum sırasında müşteri tarafından oluşturulur.
  4. Email ve şifre ile giriş yapın.
  5. Giriş sonrası normal müşteri modunda varsayılan ekran Dashboard olur.
Güvenlik notu: Varsayılan admin/admin hesabı yoktur. İlk admin şifresi kurulum sırasında müşteri tarafından belirlenir.

Giriş yapılamazsa

  • Sunucu adresi ve port doğru mu kontrol edin.
  • Tarayıcıda /api/health/ready adresini açın.
  • Şifre unutulduysa Admin yetkili kullanıcıdan yeni kullanıcı daveti veya şifre reset akışı istenmelidir.
  • Hiç admin yoksa bu normal kullanıcı ekranından çözülemez; kurulum sorumlusu ile iletişime geçin.

Sol menü, modülleri kategori bazında gösterir. Üst bölümde aktif kullanıcı, tema seçimi, menüyü daraltma ve çıkış kontrolleri bulunur.

Dashboard

Infrastructure

Virtualization

VMware cluster, ESXi host, VM, datastore ve snapshot görünümü.

Menüde bazı ekranlar entegrasyon yapılmadan boş veya sınırlı veri gösterebilir. Bu normaldir. Örneğin VMware ekranları için önce vCenter entegrasyonu kaydedilip senkronizasyon çalıştırılmalıdır.

4. Günlük Kontrol Akışı

Operasyon ekibi her gün aşağıdaki kısa kontrol akışını izleyebilir.

  1. Dashboard > Genel Sağlık ekranını açın.
  2. Kritik alarm, offline cihaz, datastore doluluk ve VPN durum özetlerini kontrol edin.
  3. Dashboard > Kritik Alarmlar ekranında yeni alarmları kaynak bazında filtreleyin.
  4. Integrations > Sync Status ekranında entegrasyonların bağlı olduğunu doğrulayın.
  5. Settings > License ekranında lisans süresi ve limit kullanımına haftalık bakın.
  6. Olay varsa ilgili detay ekranına gidip alarm kaynağını doğrulayın.

Entegrasyon durumu Bağlı veya sağlıklı görünmeli Credential, ağ erişimi ve TLS sertifika ayarlarını kontrol edin.

5. Dashboard Kullanımı

Dashboard, ortamın hızlı sağlık ekranıdır. Amaç, ekibin her modüle tek tek girmeden kritik durumu görmesidir.

Genel Sağlık

  • VMware host, VM, datastore ve snapshot özetlerini gösterir.
  • NMS/switch cihazlarının online/offline durumunu özetler.
  • Firewall, IPsec ve SSL-VPN bilgilerini hızlı kartlar halinde gösterir.
  • Kritik alarm ve bağlantı sorunlarını öncelikli görünür yapar.

Kritik Alarmlar

  • Alarm kaynağına göre filtreleyin: Tümü, Firewall, Switch, VMware.
  • Arama kutusu ile alarm kodu, başlık, IP veya cihaz adına göre arayın.
  • Config değişikliği alarmlarında eski/yeni değer detaylarını inceleyin.
  • Alarm detayındaki ham veri, kök neden analizi için kullanılabilir.
Dashboard bir özet ekranıdır. Kök neden analizi için alarmın ilgili modül detayına gidin: VMware alarmı için Virtualization ekranları, switch alarmı için NMS, firewall alarmı için Security/Firewall ekranları.

6. Alarm Yönetimi

Alarm sistemi entegrasyonlardan gelen gerçek veriye göre çalışır. Mock veya tahmini veri üretmemesi beklenir. Bu nedenle veri kaynağına erişilemiyorsa ilgili alarm oluşmayabilir.

Alarm inceleme adımları

  1. Dashboard > Kritik Alarmlar ekranına girin.
  2. Önce severity değerine bakın: Kritik, Yüksek, Orta, Düşük.
  3. Kaynak tipini belirleyin: firewall, switch/NMS veya VMware.
  4. Alarm mesajındaki cihaz, IP, port, policy veya VM bilgisini not alın.
  5. İlgili detay ekranında durumu doğrulayın.
  6. Gerçek olay ise operasyon prosedürünü çalıştırın; yanlış pozitif ise alarm kuralı/cooldown ayarını gözden geçirin.

Alarm kuralları

Settings > Alert Rules ekranından alarm tanımları ve bildirim ayarları yönetilir.

  • Alarm tanımlarını etkin/pasif yapabilirsiniz.
  • Email bildirimini alarm bazında açıp kapatabilirsiniz.
  • SMTP host, port, kullanıcı, şifre ve alıcı listesi kaydedilebilir.
  • Send Test Email ile bildirim ayarı test edilir.
  • Yeni kurulumda alarm katalog verisi eksikse seed işlemiyle tanımlar oluşturulabilir.
Alarmı kapatmak olayı çözmez. Alarm kapatma işlemi sadece tespit kuralını susturur. Kalıcı çözüm cihaz, firewall, vCenter veya network tarafındaki kök nedenin giderilmesidir.

7. Lokasyon, Rack ve Cihaz Envanteri

InfraScope fiziksel envanteri hiyerarşik modelle tutar: Organization > Building > Floor > Room > Rack > Device.

Lokasyon yönetimi

  1. Infrastructure > Locations ekranına girin.
  2. Önce organizasyon/firma kaydını oluşturun.
  3. Organizasyon altında bina ekleyin.
  4. Bina altında kat, kat altında oda, oda altında rack ekleyin.
  5. Yanlış kayıtları düzenlemek için edit ikonunu, kaldırmak için delete ikonunu kullanın.

Rack yönetimi

  • Infrastructure > Racks ekranından rack listesini izleyin.
  • Rack adı, lokasyon ilişkisi, kapasite ve operasyonel durum bilgilerini düzenleyin.
  • Rack silmeden önce bağlı cihaz ve lokasyon ilişkilerini kontrol edin.

Cihaz yönetimi

  1. Infrastructure > Devices ekranına girin.
  2. Add Device ile cihaz adı, IP, tip, durum, lokasyon/rack bilgilerini girin.
  3. Arama ve filtreleri kullanarak cihazı bulun.
  4. Edit ile bilgileri güncelleyin.
  5. Silme işlemleri geri alınamaz; üretim ortamında silmeden önce doğrulama yapın.
En iyi sonuç için önce lokasyon ağacını oluşturun, sonra cihazları bu lokasyonlara bağlayın. Böylece topology ve dashboard ekranları daha anlamlı veri gösterir.

8. Network ve NMS Kullanımı

Topology

Network > Topology ekranı altyapının görsel haritasıdır. Bina, mantıksal, fiziksel ve hiyerarşi görünümleriyle farklı seviyelerde inceleme yapılabilir.

  • Yakınlaştırma yaptıkça bina, kat, oda ve cihaz detayları kademeli görünür.
  • Breadcrumb ile üst seviyeye geri dönün.
  • Bağlantı yönetimi ile binalar veya cihazlar arası linkleri modelleyin.
  • Gerekirse mevcut görünümü PNG olarak dışa aktarın.

Switch/NMS cihazları

  1. Network > Add Device ekranından switch veya network cihazı ekleyin.
  2. IP adresi, vendor, SNMP ve gerekiyorsa SSH bilgilerini girin.
  3. SNMP ile arayüz, VLAN, port durumu gibi bilgiler izlenir.
  4. SSH ile config backup alınabilir.
  5. Network > Switches ekranından bağlantı durumlarını takip edin.

Config Backups

  • Network > Config Backups cihaz konfigürasyon yedeklerini gösterir.
  • FortiOS, Cisco IOS/NX-OS ve HP Comware gibi cihazlarda vendor komutları farklı olabilir.
  • Config değişikliği alarmı geldiğinde bu ekranı kullanarak önceki ve yeni sürüm karşılaştırılabilir.
SNMP timeout veya SSH bağlantı hatası varsa cihaz tamamen bozuk anlamına gelmez. Önce network erişimi, firewall ACL, SNMP community/v3 credential ve SSH kullanıcı yetkisini kontrol edin.

9. VMware Sanallaştırma

VMware ekranları vCenter entegrasyonu ile dolar. Entegrasyon yapılmadan cluster, host, VM, datastore ve snapshot ekranları boş görünebilir.

vCenter bağlama

  1. Integrations > VMware ekranına girin.
  2. vCenter URL, kullanıcı adı ve şifre bilgilerini girin.
  3. Self-signed sertifika kullanılıyorsa kurulumda CA sertifikası yolu tanımlanmış olmalıdır.
  4. Test Connection ile bağlantıyı doğrulayın.
  5. Save Configuration ile kaydedin.
  6. Start Synchronization ile manuel senkronizasyon başlatın.

VMware modül ekranları

Ekran Ne için kullanılır?
Virtualization > Clusters Cluster envanteri ve genel kapasite görünümü.
Virtualization > ESXi Hosts Host bağlantı durumu, CPU, bellek ve host envanteri.
Virtualization > Virtual Machines VM listesi, power state, kaynak bilgileri ve guest IP bilgileri.
Virtualization > Datastores Datastore kapasitesi, kullanım oranı ve kritik doluluk takibi.
Virtualization > Snapshots Eski veya çoklu snapshot risklerini izleme.
VMware olayları alarm motoruna da veri sağlar. VM reconfigure, clone, datastore doluluk ve snapshot riskleri bu entegrasyon üzerinden izlenir.

10. Firewall ve Güvenlik Ekranları

Security menüsü FortiGate/FortiAnalyzer ve firewall politika görünürlüğü için kullanılır. Cihaz üzerinde değişiklik yapmadan önce kurum değişiklik yönetimi sürecini izleyin.

Ekran Kullanım amacı
Security > Firewall View Firewall politika, kural ve ağ güvenliği görünümü.
Security > Config Revisions Config snapshot ve değişiklik farklarını inceleme.
Security > Virtual IPs DNAT/VIP ile dışa açılan servisleri izleme.
Security > Web Analytics Web erişim analitiği ve FortiAnalyzer kaynaklı görünürlük.
Security > Quarantine Şüpheli IP veya varlıklar için karantina görünümü.
Security > Firewall Policies Kural listesi, kaynak/hedef/servis ve aksiyon inceleme.
Security > IPsec Tunnels Site-to-site VPN tünel durumlarını izleme.
Security > SSL-VPN SSL-VPN oturum ve erişim durumlarını izleme.
Security > Risky Rules Geniş kaynak/hedef, any-any, riskli servis gibi kural risklerini bulma.

Riskli kural inceleme

  1. Risky Rules ekranında kritik ve yüksek severity kayıtları inceleyin.
  2. Kuralın kaynak, hedef, servis ve aksiyon alanlarını kontrol edin.
  3. İş ihtiyacı yoksa kuralın daraltılması için firewall değişiklik talebi açın.
  4. Değişiklik sonrası sync çalıştırıp riskin kapanıp kapanmadığını doğrulayın.

11. Servis ve Bağımlılık Haritası

Services menüsü uygulama, servis ve bağımlılık envanteri için kullanılır. Bu modül, teknik envanter ile iş servisleri arasında ilişki kurmak için tasarlanmıştır.

  • Services > Applications: Uygulama veya servis bileşenlerinin çalışma durumunu gösterir.
  • Services > Services: Servis kayıtlarını ve temel bilgileri listeler.
  • Services > Dependencies: Servisler, cihazlar ve altyapı bileşenleri arasındaki bağımlılıkları gösterir.
Bu ekranlar demo ve operasyonel modelleme için kullanılabilir. Gerçek servis haritası değeri, müşteri envanteri düzenli girildiğinde artar.

12. Entegrasyonları Yönetme

Entegrasyonlar uygulamanın canlı veri kaynaklarıdır. Yanlış credential veya ağ erişimi sorunu, dashboard ve alarmların eksik görünmesine neden olabilir.

VMware

  • vCenter URL, kullanıcı adı ve şifre gerekir.
  • Bağlantıyı test edin, sonra kaydedin.
  • Senkronizasyon sonrası cluster, host, VM, datastore ve snapshot ekranlarını kontrol edin.

Firewall / FortiGate

  • REST API için yönetim IP/URL ve kullanıcı veya token bilgisi gerekir.
  • SNMP ile interface ve port durumu izlenebilir.
  • SSH ile config backup alınabilir.
  • Policy, VIP, SSL-VPN, IPsec ve config revision ekranları FortiGate verisine bağlıdır.

FortiAnalyzer

  • FortiAnalyzer log ve güvenlik olayları için kullanılır.
  • Session tabanlı erişim ve API key modeli desteklenir.
  • Hesap kilitlenirse FortiAnalyzer tarafında kullanıcı durumu kontrol edilmelidir.

Sync Status

Integrations > Sync Status ekranı tüm entegrasyonların sağlık özetidir. Bağlı, hata, bağlantı kesildi veya senkronize durumlarını buradan izleyin.

Self-signed sertifikalı FortiAnalyzer, FortiGate veya vCenter için global TLS bypass kullanılmaz. Sertifika CA dosyası kurulumda ./certs altına eklenmeli ve ilgili env değişkeniyle tanımlanmalıdır.

13. Ayarlar, Kullanıcılar ve Lisans

Organizations

Firma/organizasyon kayıtlarını yönetin. Lokasyon hiyerarşisi ile birlikte kullanılınca envanter raporları ve topology daha anlamlı hale gelir.

Users & Roles

  • Kullanıcı listesini görüntüleyin.
  • Admin, editor, viewer gibi rol ayrımlarını kurum politikasına göre uygulayın.
  • Aktif olmayan veya ayrılan personelin erişimini kapatın.

Invitations

  • Yeni kullanıcıları davet edin.
  • Davet edilen kişinin email adresini doğru girin.
  • Davet akışında kullanıcı kendi şifresini belirlemelidir.

Audit Log

Kullanıcı aksiyonları, kritik değişiklikler ve yönetim işlemleri audit log ekranından izlenir. Olay inceleme sırasında kim, ne zaman, hangi işlemi yaptı sorusunun ilk kontrol noktasıdır.

API Keys

  • Harici sistemlerin InfraScope API kullanması gerekiyorsa API key oluşturun.
  • Key değerini sadece oluşturma anında güvenli şekilde paylaşın.
  • Kullanılmayan keyleri kapatın veya silin.

License

Settings > License müşteri lisans durum ekranıdır.

  • Tier: Trial, Standard veya Enterprise.
  • Device ve user kullanım limitleri.
  • Lisans bitiş tarihi ve kalan gün.
  • Grace mode durumu.
  • Machine ID ve masked license key.
Lisans anahtarı ve API key bilgileri ekran görüntüsüyle veya e-posta zincirlerinde paylaşılmamalıdır. Yetkisiz kişilere verilen keyler müşteri ortamını riske atabilir.

14. Önerilen Operasyon Rutini

Günlük

  • Dashboard genel sağlık kontrolü.
  • Kritik alarm kontrolü.
  • Offline switch, ESXi host, VPN tüneli veya kritik datastore var mı kontrolü.
  • Integration Status ekranında bağlantı sorunları kontrolü.

Haftalık

  • Risky Rules ekranında yeni yüksek riskli firewall kuralı var mı bakın.
  • Config Revisions ekranında beklenmeyen değişiklikleri inceleyin.
  • Datastore ve snapshot ekranlarında kapasite/operasyon riski kontrol edin.
  • Lisans kullanım limitlerini kontrol edin.

Aylık

  • Kullanıcı listesini gözden geçirin.
  • API keys ve davetleri temizleyin.
  • Alarm email alıcı listesini güncelleyin.
  • Envanterde silinmiş veya taşınmış cihazları düzeltin.
  • Config backup kapsamasını örnek cihazlarla doğrulayın.
