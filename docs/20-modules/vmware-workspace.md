# VMware integration settings workspace

The VMware settings workspace separates stored connection metadata, explicit connection tests and inventory synchronization. Initial rendering reads only workspace metadata and the current account; it does not authenticate to vCenter or collect inventory. This is a single-installation settings view, not a new tenant boundary.

## Settings and profile identity

GET /api/integrations/vmware?type=workspace returns deterministic VMware profile metadata and the most recent sync log with private/no-store. Only password presence is exposed; ciphertext, raw log messages and diagnostic details are omitted. The existing config/inventory/cache endpoints remain supported. The former blanket public VMware HTTP-cache rule is removed so it cannot append public directives to private settings responses; the existing source-scoped server inventory cache remains in use. Multiple profiles require explicit selection; updates use immutable configId and preserve the selected name and other profiles.

The workspace sends createOnly for its first-profile save. A same-name record or concurrent unique conflict returns 409 rather than overwriting another profile. Existing name-based legacy upserts remain compatible. By-ID edits send the observed updatedAt version and use a database compare-and-set on configuration, enabled state, interval and update time, so stale/concurrent edits cannot overwrite a credential or schedule change. A 409 preserves the draft and asks for undo/refresh. Callers omitting the optional client version retain the pre-existing API contract but still get the in-flight compare-and-set boundary.

Authority validation runs on the server before writes or draft source construction. Paths, URL user-info, query/fragment, whitespace-only host/user and invalid ports are rejected. Stored protocol/trailing slash normalization remains supported. The interval is an integer from 1 to 1440 minutes. An empty password preserves the same profile's secret only when host/username are unchanged; a changed identity requires a new secret. Saved secrets use existing encryption. Disabled profiles stay disabled unless explicitly enabled.

## Test, sync and presentation boundaries

Saved tests use the selected profile's server-side secret; draft tests require the entered password and do not save it. Both use the existing full REST/ESXi/snapshot/Python capability test and owned session cleanup. Connection success is evidence for that test/target/time, not continuous health. Save/refresh/profile changes retire test evidence, and draft edits retire draft-test evidence. Manual session results are cleared after settings changes.

Manual sync requires devices/write (ADMIN or EDITOR), an enabled selected profile and a clean form. Settings and both connection tests require settings/write (ADMIN). API guards recheck the current ACTIVE database user. A sync response includes configId and the workspace verifies it before displaying an outcome. Partial/failed outcomes remain distinct from success; missing counts/times remain unknown. Persistent lastSyncAt/status and latest log details are labelled separately from a session's manual result. Counts describe processed records, not total live inventory. Datastore processing has no created/updated breakdown.

The datacenters flag is preserved but not editable because the current sync implementation does not independently use it. Module selections apply to inventory import, not live reads or connection-test scope. Legacy thumbprint is stored metadata and is explicitly not certificate pinning; existing TLS trust policy is unchanged. Dirty forms block refresh/profile changes/sync and provide explicit undo. Failed reads retain clearly stale metadata and disable operations. HTTP status and response shape/identity must pass; unknown write outcomes block retries until explicit successful refresh. Auth failures are recognized even with non-JSON bodies. No automatic write retry is added.

The existing manual sync organization/default selection, scheduler, process-local cache lifetime and legacy client/session design are unchanged. The setting interval continues to feed the saved syncInterval used by the existing scheduler. In-flight external work is not cancelled by UI timeout/refresh, and an already-running source can finish using its initial snapshot.

## Verification

npm run test:vmware-workspace uses real settings/API/encryption modules with synthetic ORM/source/transport adapters. VMware cache, collection, health and integration-permission regressions cover their existing contracts. The guarded disposable browser/PostgreSQL spec vmware-settings-workspace.spec.ts covers metadata, encryption, exact-target edits, invalid input, concurrency, first creation, current permissions and responsive/error states. Allowed connection/sync UI actions use browser-local fixture responses; real vCenter operations are not run for QA. Signed-session rejected requests execute actual route authorization before any source access. Existing Python contract tests run in an isolated runtime with the pinned SDK and loopback-only synthetic SOAP fixtures. See design-qa.md for actual results and coverage limits.
