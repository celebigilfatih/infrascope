Gerekenler: Windows yönetici yetkisi, vSphere yöneticisinin hazırladığı kalıcı VM, internet erişimi ve müşteriye ait InfraScope lisansı. GitHub hesabı/tokenı, Git, Node.js veya elle PostgreSQL kurulumu gerekmez.

Yeni kurulum / mevcut kurulum ayrımı

İlk kurulum hedefi boş olmalıdır. Mevcut müşteri kurulumu varsa üzerine yeni kurulum yapmayın; mevcut kurulum bölümüne geçin. Başarısız bir adımdan sonra ilerlemeyin; önce ilgili hatayı giderin.

Bu belge yerel kullanım içindir: tarayıcı Windows VM içinde açılır. Farklı bir bilgisayardan erişim için HTTPS ve uygulama adresi ayrıca yapılandırılmalıdır.

01 / Altyapı yöneticisi

vSphere ve Windows hazırlığı

AyarÖnerilen başlangıç yapılandırması
Kaynak4 vCPU · 16 GB RAM · 150 GB sanal disk. Bunlar başlangıç önerisidir; cihaz kapasitesi garantisi değildir. Veritabanı ve yedek büyümesini izleyin.
İşletim sistemiMicrosoft tarafından halen desteklenen, güncellemeleri yapılmış Windows 11 Pro / Enterprise x64. VMware Tools kurulu olmalı.
Firmware / güvenlikEFI/UEFI, Secure Boot ve vTPM 2.0. vTPM için etkin ve yedeklenmiş bir Key Provider gerekir.
AğKalıcı IP veya DHCP rezervasyonu, doğru DNS/zaman ve izlenecek cihazlara yönlendirme.
  1. Windows'u kapatın; vSphere Client içinde VM → Edit Settings → CPU → Hardware Virtualization yolunu açın.
  2. Expose hardware assisted virtualization to the guest OS seçeneğini işaretleyin. Bu, WSL2 için iç içe sanallaştırmayı açar.
  3. VM'yi başlatın, Windows güncellemelerini ve VMware Tools kurulumunu tamamlayın.
  4. Kurulumu ve işletimi sürdürecek aynı Windows hesabıyla oturum açın. Başka kullanıcı altında açılan Docker WSL2 ortamı farklı olabilir.

AMD hostlarda Broadcom WSL2 için ESXi 7.0 U3o, 8.0 U1c veya sonraki uygun sürümleri belirtir. vSphere/CPU uyumluluğunu altyapı yöneticisi doğrulamalıdır. Broadcom destek koşulları

Key Provider ve vTPM

Mevcut uygun sağlayıcıyı kullanın. Yeni sağlayıcı gerekiyorsa vCenter → Configure → Security → Key Providers üzerinden kurum standardına göre oluşturup yedekleyin. .p12 yedeği ve varsa parolası bağımsız güvenli depoda tutulmalıdır. vTPM aygıtını sonradan kaldırmayın. Resmi hazırlık adımları

03 / Windows oturumu

Docker Desktop'ı kurun ve başlatın

  1. Docker'ın resmi indirme sayfasından Windows x86_64 kurucusunu indirin; ARM paketini seçmeyin.
  2. Kurucuda WSL2 arka ucunu kullanın: Use WSL 2 instead of Hyper-V. Menü sürüme göre değişebilir.
  3. Gerekirse Windows'u yeniden başlatın. Docker Desktop'ı aynı işletim hesabında açın; motorun çalışmasını bekleyin.
  4. Settings → General altında Use the WSL 2 based engine ve Start Docker Desktop when you sign in seçeneklerini açın. Linux containers motorunu kullanın.

04 / PowerShell

{{VERSION}} kurucusunu indirin ve doğrulayın

Aşağıdaki bloğun tamamını kopyalayın. Kurucu ayrı bir Downloads klasörüne indirilir; asıl kurulum hedefi boş kalır. Betik dosyası SHA256 ile doğrulanmadan sonraki adıma geçmeyin.

PowerShell · indir ve SHA256 doğrula
& {
    $ErrorActionPreference = 'Stop'
    [Net.ServicePointManager]::SecurityProtocol = `
        [Net.ServicePointManager]::SecurityProtocol -bor `
        [Net.SecurityProtocolType]::Tls12

    New-Item -ItemType Directory `
        -Path 'C:\InfraScope\Downloads' -Force | Out-Null
    Set-Location 'C:\InfraScope\Downloads'

    $downloadUrl = 'https://github.com/{{REPOSITORY}}/releases/download/v{{VERSION}}/install-infrascope.ps1'
    Invoke-WebRequest -Uri $downloadUrl `
        -OutFile '.\install-infrascope.ps1' -UseBasicParsing

    $expectedHash = '{{BOOTSTRAP_SHA256}}'
    $actualHash = (Get-FileHash '.\install-infrascope.ps1' `
        -Algorithm SHA256).Hash.ToLowerInvariant()

    if ($actualHash -ne $expectedHash) {
        throw 'SHA256 uyusmuyor. Kurulumu baslatmayin.'
    }
    Unblock-File '.\install-infrascope.ps1'
    Write-Host 'Kurucu dogrulandi. Sonraki adima gecebilirsiniz.'
}

Kontrol: Kurucu dogrulandi. Sonraki adima gecebilirsiniz. mesajı görünür. Bu blok InfraScope'u henüz kurmaz.

Beklenen hash, {{VERSION}} sürümünün install-infrascope.ps1 dosyasına aittir. Kaynak kod sayfasındaki “Code → Download ZIP” müşteri kurulum paketi değildir. Yayımlanan SHA256 dosyası

05 / PowerShell · yeni kurulum

InfraScope {{VERSION}}'yi kurun

Docker motoru çalışırken bu bloğu uygulayın. C:\InfraScope\infrascope klasörü henüz bulunmamalı veya tamamen boş olmalıdır.

PowerShell · yeni ve boş hedefe kurulum
Set-Location 'C:\InfraScope\Downloads'

powershell.exe -NoProfile -ExecutionPolicy Bypass `
    -File .\install-infrascope.ps1 `
    -Version {{VERSION}} `
    -Repository '{{REPOSITORY}}' `
    -Destination 'C:\InfraScope\infrascope' `
    -ProjectName 'infrascope-musteri' `
    -AppPort 8170

Kurucu sürüm paketini doğrular, imajları sabit SHA256 özetleriyle indirir, benzersiz kurulum anahtarları oluşturur ve boş veritabanına şemayı kurar. İnternet hızına göre ilk indirme zaman alabilir. Servislerin sağlıklı olması için son aşamada en fazla 300 saniye bekler.

Kontrol: İşlem hatasız biter ve Installation ready: http://localhost:8170/setup mesajı görünür. Tarayıcı otomatik açılabilir.

İşlem yarım kalırsa

Hedef klasörü silmeyin veya yeni proje adı seçmeyin. Kurulum dosyaları hazırlanmışsa, sorunu giderdikten sonra aynı klasördeki install.ps1 ile devam edin. İndirme henüz dosyaları hazırlamadan başarısız olmuş ve hedef hâlâ boşsa başlatıcı tekrar çalıştırılabilir.

-ExecutionPolicy Bypass yalnız başlatılan PowerShell süreci içindir; sistemin genel politikasını değiştirmez. Kurumun zorunlu politikası engellerse BT yöneticisiyle ilerleyin.

06 / VM içindeki tarayıcı

Lisansı etkinleştirin ve ilk yöneticiyi oluşturun

Windows VM'nin kendi tarayıcısında http://localhost:8170/setup adresini açın.

  1. Müşteriye ait InfraScope lisans anahtarını etkinleştirin.
  2. Kurum bilgilerini tamamlayın.
  3. İlk yönetici hesabını oluşturup giriş yapın.

Hazır yönetici hesabı veya varsayılan parola yoktur. Yönetici parolasını ve lisans anahtarını kurumun parola kasasında saklayın.

“Localhost” hangi bilgisayardır?

Adres, tarayıcının açıldığı bilgisayarı ifade eder. Kendi bilgisayarınızın tarayıcısından bu adrese gitmek VM'yi açmaz. VM'ye uzak masaüstüyle bağlanıp tarayıcıyı orada açın. Ağdan kullanım için ayrıca HTTPS, URL ve erişim yapılandırması gerekir.

08 / İşletim sorumlusu

Kesintisiz çalışma ve yedek

Windows'un uykuya geçmesini kapatın. Docker Desktop için oturum açıldığında başlatmayı etkinleştirin. Windows oturumu açılmadan Docker Desktop'ın çalışacağı varsayılmamalıdır. VM yeniden başlayınca işletim hesabıyla oturum açıp motorun ve uygulamanın geri geldiğini kontrol edin. 24 saat izleme için bu işletim koşulu sağlanmalıdır.

Şifreli taşınabilir yedek

  1. C:\Private\infrascope-recovery-passphrase.txt dosyasını yetkili yönetici hazırlasın. İçeriği en az 16 baytlık, tek satırlık güçlü bir kurtarma parolası olsun; UTF-8 biçiminde kaydedilsin.
  2. Dosyanın Windows güvenlik izinlerini yalnız işletim sorumlusu ve yetkili yöneticilerin okuyabileceği şekilde sınırlandırın. Parolayı bu kılavuza veya komut geçmişine yazmayın.
  3. Aşağıdaki komutu çalıştırın. Ekranda yazılan .isbackup dosyasını VM dışındaki güvenli depoya alın; parolayı ayrı kasada saklayın.
PowerShell · parola dosyası hazırlandıktan sonra
Set-Location 'C:\InfraScope\infrascope'

powershell.exe -NoProfile -ExecutionPolicy Bypass `
    -File .\backup.ps1 `
    -PassphraseFile 'C:\Private\infrascope-recovery-passphrase.txt'

Yedek backups klasörüne yazılır. Otomatik backups\database yedeği tek başına taşınabilir kurulum yedeğinin yerini tutmaz. Özel CA sertifikaları kullanılıyorsa certs klasörünü ayrıca güvenli yedekleyin. Geri yükleme için kurulum paketindeki BACKUP_OPERATIONS.md prosedürünü kullanın; yedeği ayrı ortamda geri yükleyerek doğrulayın.

Planlı durdurma ve başlatma

Aşağıdaki iki blok farklı zamanlarda kullanılmak içindir. Durdurma, izlemeyi ve uygulamayı keser.

PowerShell · yalnız planlı durdurma gerektiğinde
Set-Location 'C:\InfraScope\infrascope'
docker compose -f docker-compose.yml -f release-images.yml stop
PowerShell · daha önce durdurulan servisleri başlat
Set-Location 'C:\InfraScope\infrascope'
docker compose -f docker-compose.yml -f release-images.yml start
Verileri koruyun

.env, data, certs, yedekler ve Docker veritabanı volume'u müşteriye aittir. docker compose down --volumes çalıştırmayın. Docker Desktop “Factory reset”, volume silme, WSL dağıtımı kaldırma veya geniş kapsamlı Docker temizliği müşteri verisini kaybettirebilir.

Alternatif yol / zaten kurulu sistem

Mevcut kurulumdan {{VERSION}}'ye güncelleme

Bu bölüm yeni kurulum tamamlandıktan sonra uygulanacak bir adım değildir. Yalnız mevcut, online güncelleme betikleri bulunan eski sürüm kurulumu için kullanın. Kurulum yolu farklıysa aşağıdaki yolu mevcut klasörle değiştirin; proje adı ve portu değiştirmeyin.

Önce kullanıcı işlemlerini ve dışarıdan veri yazan işleri bakım penceresinde durdurun. Kurtarma parolası dosyası hazır olmalı; yedekleme ile servislerin durması arasında yeni yazmalar oluşmamalıdır.

PowerShell · mevcut kurulum, bakım penceresinde
Set-Location 'C:\InfraScope\infrascope'

powershell.exe -NoProfile -ExecutionPolicy Bypass `
    -File .\update.ps1 `
    -Version {{VERSION}} `
    -Repository '{{REPOSITORY}}' `
    -PassphraseFile 'C:\Private\infrascope-recovery-passphrase.txt'

Güncelleyici sürümü ve imajları doğrular; zorunlu şifreli yedek başarısızsa güncellemeyi durdurur. Müşterinin ayarlarını, anahtarlarını ve verilerini korur. VERSION değerini önceden elle değiştirmeyin. Tamamlanmış aynı sürümü yeniden çalıştırmak yeni güncelleme yapmaz.

.update-state.json varsa silmeyin: sorunu giderip aynı klasör, sürüm ve depoyla komutu yeniden çalıştırın. Migration sonrasında elle eski imaja dönmeyin; uyumlu yedekten kurtarma prosedürünü izleyin. Eski çevrimdışı pakette update.ps1 bulunmuyorsa geçişi kurulum sorumlusuyla planlayın; dağıtım dosyalarını mevcut müşteri ayarlarının üzerine açmayın.

Sorun giderme

Sık karşılaşılan hatalar ve çözümleri

Başlığa tıklayarak çözümü açın. Sorun giderme komutları yalnız ilgili hata için kullanılmalıdır; bütün blokları sırayla çalıştırmayın.

01 · Windows 11 kurulumu vTPM / Key Provider hatası veriyor

vCenter'da etkin bir Key Provider ve sağlayıcının güvenli yedeği bulunmalı. VM kapalıyken Trusted Platform Module ekleyin, EFI ve Secure Boot ayarlarını kontrol edin. Kurumun mevcut sağlayıcısını silmeyin; Windows gereksinimlerini atlayan kurulum kullanmayın. Broadcom KB 396090

02 · WSL2 / Docker: 0x80370102, “Virtualization support not detected”
  1. VM'yi kapatıp vSphere CPU altında Expose hardware assisted virtualization to the guest OS ayarını kontrol edin.
  2. Windows açıldıktan sonra WSL'yi güncelleyin. Virtual Machine Platform kapalıysa yönetici PowerShell'de aşağıdaki bloğu uygulayıp Windows'u yeniden başlatın.
Yönetici PowerShell · yalnız eksik Windows bileşenlerini etkinleştirme
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart

İki komutun da başarılı olduğunu kontrol edin; yeniden başlatıp wsl --update çalıştırın. Devam ederse host CPU/ESXi uyumluluğunu altyapı yöneticisi incelemeli. Bu vSphere ortamında Hyper-V hostuna ait Set-VMProcessor komutunu kullanmayın. Microsoft WSL hata giderme

03 · “wsl” bulunamıyor veya “WSL needs updating”

Güncel Windows 11 üzerinde yönetici PowerShell kullanın. WSL kurulum ve güncelleme bölümünü uygulayın. Microsoft Store erişimi kurum tarafından engelleniyorsa BT onayıyla alternatif indirme komutunu kullanabilirsiniz:

Yönetici PowerShell · alternatif WSL güncelleme kaynağı
wsl --update --web-download

Bu seçenek GitHub erişimi gerektirir. Başarıdan sonra Docker Desktop'ı açın.

04 · “docker” bulunamıyor / Docker Engine bağlantı hatası / named pipe hatası

Docker Desktop'ın kurulu ve açık olduğunu kontrol edin. Kurulumdan sonra eski terminali kapatıp yeni PowerShell açın; aynı işletim kullanıcısında çalışın. Docker Desktop motoru çalışır duruma geldikten sonra docker version ve docker info ile yeniden kontrol edin. WSL hatası varsa önce onu çözün. Docker Desktop'ı fabrika ayarlarına döndürmeyin.

05 · “requires Docker Linux x86_64” / Windows containers seçili

Docker Desktop menüsünde gerekiyorsa Switch to Linux containers seçin, WSL2 motorunu kullanın. docker info --format '{{.OSType}}/{{.Architecture}}' çıktısını kontrol edin. Windows/ARM motoru bu müşteri paketine uygun değildir; VM ve Docker x86_64 olmalıdır.

06 · “Destination must be empty” / kurulum yarım kaldı

Yeni kurulum başlatıcısı dolu hedefe yazmaz. Mevcut kurulum varsa güncelleme yolunu kullanın. Bu ilk kurulumun dosyaları hazırlandıktan sonra hata olduysa Docker/ağ hatasını giderip aşağıdaki komutla devam edin. Bu devam komutu var olan anahtarları korur; proje adı veya portu yeniden belirtmez.

PowerShell · yalnız hazırlanmış ilk kuruluma devam
Set-Location 'C:\InfraScope\infrascope'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1

install.ps1 veya release.json yoksa klasörü silmeyin; eksik/karışmış dosyaları kurulum sorumlusuyla inceleyin. Dosyalar henüz oluşmadı ve hedef boşsa ilk kurulum tekrar denenebilir.

07 · SHA256 / paket manifesti doğrulaması başarısız

İşlemi durdurun. Kurucuyu yalnız resmi {{VERSION}} sürüm sayfasından yeniden indirin ve hash kontrolünü tekrar yapın. Güvenlik kontrolünü kaldırmayın, beklenen hash'i gelen dosyaya göre değiştirmeyin. ZIP/manifest uyuşmazlığı sürerse sürüm adı ve hata mesajıyla destek isteyin.

08 · GitHub / GHCR indirme hatası, 401 / 403 / 404 / “denied”

Resmi {{VERSION}} release ve müşteri imajları herkese açıktır; giriş/token gerekmez. GitHub API hız sınırı, eski oturum tokenı, DNS/proxy, kurumsal filtre veya sertifika zinciri farklı nedenlerdir. Hata metnini inceleyin; 403 hız sınırında belirtilen yenileme zamanını bekleyin. 404 durumunda repo, sürüm ve indirme adresinin v{{VERSION}} olduğuna bakın. Tokenı kılavuza veya .env dosyasına yazmayın.

PowerShell · temel HTTPS bağlantısı, tam indirme testi değildir
Test-NetConnection api.github.com -Port 443
Test-NetConnection ghcr.io -Port 443
Test-NetConnection registry-1.docker.io -Port 443
Test-NetConnection lisans.webmahsul.com.tr -Port 443

GitHub Release yönlendirme/indirme ve imaj katmanı alan adları da erişilebilir olmalıdır. HTTPS sertifika hatasını denetimi kapatarak aşmayın; BT ekibi proxy/CA zincirini düzeltmeli. Yanlış veya özel eski imaj adresine elle geçmeyin; release-images.yml dosyasını koruyun.

09 · 8170 portu kullanımda / “port is already allocated”

Portu kullanan hizmeti belirleyin; rastgele işlem sonlandırmayın.

PowerShell · dinleyen işlemi belirleme
Get-NetTCPConnection -LocalPort 8170 -State Listen `
    -ErrorAction SilentlyContinue |
    Select-Object LocalAddress, LocalPort, OwningProcess

Çakışma ilk kurulum sırasında oluştuysa ve kurulum dosyaları hazırsa aynı klasörde aşağıdaki komutla portu 8171 yapıp devam edin. Proje adı ve veri yerinde kalır.

PowerShell · yalnız ilk kurulumun port çakışmasını giderme
Set-Location 'C:\InfraScope\infrascope'
powershell.exe -NoProfile -ExecutionPolicy Bypass `
    -File .\install.ps1 -AppPort 8171

Bundan sonra tarayıcı ve sağlık kontrolü adresinde 8171 kullanın. Henüz kurulum başlamadıysa ilk başlatıcıdaki -AppPort 8170 değerini -AppPort 8171 yapabilirsiniz. Çalışan kurulumun adresini değiştirmeyi ayrıca planlayın.

10 · “running scripts is disabled” / dosya engellendi / erişim reddedildi

Dosyayı doğruladıktan sonra kılavuzdaki powershell.exe -NoProfile -ExecutionPolicy Bypass -File ... çağrısını kullanın. Kurumun Group Policy kısıtlaması varsa BT yöneticisiyle ilerleyin; genel politikayı veya korumaları kapatmayın. Klasöre erişim reddinde kurulumun işletim hesabını ve NTFS izinlerini kontrol edin. Mevcut .env izinlerini herkese açmayın.

11 · Kurulum 300 saniyede tamamlanmadı / servis unhealthy / 503

Compose durumunu ve günlükleri inceleyin. Disk doluluğu, RAM yetersizliği, Docker'a ayrılan kaynaklar, imaj indirme ve veritabanı/migration hatalarını kontrol edin. İlk açılış sürüyorsa birkaç dakika sonra sağlık kontrolünü yeniden deneyin. Sorunu giderince yarım kalan ilk kurulumu install.ps1 ile sürdürün. Veritabanı volume'unu, anahtarları veya migration kayıtlarını silmeyin.

12 · “localhost” açılmıyor / yanlış yönleniyor / lisans etkinleşmiyor

Tarayıcıyı VM içinde açın; Docker motorunu, servisleri ve kullanılan portu kontrol edin. Port değiştiyse aynı yeni adresi kullanın. Lisans için https://lisans.webmahsul.com.tr erişimini, Windows tarih/saatini ve müşteri lisansını doğrulayın. Aktivasyon limiti veya makine eşleşmesi hatasında lisans sorumlusuna başvurun; data/machine-id klasörünü silmeyin ve başka müşterinin lisans önbelleğini kopyalamayın.

13 · VM yeniden başladıktan sonra uygulama çalışmıyor / ölçümler durdu

İşletim hesabıyla Windows'a oturum açın, Docker Desktop'ı başlatıp motoru bekleyin. Servisler önceki bakımda elle durdurulduysa başlatma komutunu kullanın; sağlık kontrolünü yineleyin. Uyku ayarını ve “Start Docker Desktop when you sign in” seçeneğini kontrol edin. Windows oturumu açılmadan servis devamlılığı gerekiyorsa bu Docker Desktop düzeni için işletim modeli ayrıca değerlendirilmelidir.

14 · Yedek / güncelleme başarısız, parola dosyası yok veya hatalı

Parola dosyasının mevcut, UTF-8, tek satır ve en az 16 bayt olduğunu; işletim hesabının okuyabildiğini kontrol edin. Parolayı terminale yazdırmayın. Docker motoru ve servislerin çalıştığını, boş disk alanını kontrol edin. Yedek başarısızken güncellemeyi zorlamayın. Yarım kalan güncellemede .update-state.json ve ilk yedeği koruyup aynı güncelleme komutuyla devam edin. Güncelleme öncesi yazmaları durdurmayı unutmayın.
