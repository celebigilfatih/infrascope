Lisans Sunucusu Kurulumu (Sizin Taraf)

Merkezi sunucunuzda çalışacak lisans yönetim sistemi
ℹ️
Not: Lisans sunucusu, mevcut InfraScope projesinin ta kendisidir. Ek bir yazılım kurulumu gerekmez — sadece veritabanına müşteri/lisans kayıtları eklenir.

Sunucuya Deploy Edin

InfraScope projesini kendi sunucunuza (VPS/Cloud) deploy edin:

Terminal 
# Sunucunuzda
git clone https://github.com/sirket/infrascope.git
cd infrascope

# Production ortamı için
docker compose -f docker-compose.prod.yml up -d

# Veritabanı migration'larını çalıştır
npx prisma migrate deploy

Müşteri Kaydı Oluşturun

Yeni müşteri aldığınızda veritabanına kayıt ekleyin:

PostgreSQL 
-- 1. Müşteri oluştur
INSERT INTO customers (id, company_name, contact_name, email, tier, status)
VALUES (
  gen_random_uuid()::text,
  'ABC Şirketi A.Ş.',
  'Ahmet Yılmaz',
  'ahmet@abc.com',
  'STANDARD',   -- TRIAL | STANDARD | ENTERPRISE
  'ACTIVE'
);

-- 2. Lisans anahtarı üret
INSERT INTO licenses (id, key, customer_id, tier, max_devices, max_users,
                      valid_from, valid_until, activation_limit)
VALUES (
  gen_random_uuid()::text,
  'IS-2026-ABCD-1234',     -- Müşteriye verilecek anahtar
  '<müşteri_id>',
  'STANDARD',
  100,                      -- Maksimum cihaz sayısı
  10,                       -- Maksimum kullanıcı sayısı
  NOW(),
  NOW() + INTERVAL '1 year', -- 1 yıllık geçerlilik
  1                         -- Aktivasyon limiti (kaç makine)
);

Lisans Anahtarı Formatı

Standart format: IS-{YIL}-{4 karakter}-{4 karakter}

⚠️
Her lisans anahtarı benzersiz olmalıdır. Üretim sırasında key alanına UNIQUE constraint vardır.

Müşteri Takibi

Heartbeat verilerinden kullanım istatistikleri toplanır:

İzleme Sorguları 
-- Aktif müşteriler ve kullanım durumu
SELECT c.company_name, l.key, l.tier,
       l.max_devices, l.max_users,
       l.valid_until,
       (SELECT device_count FROM license_heartbeats
        WHERE license_id = l.id
        ORDER BY created_at DESC LIMIT 1) AS last_device_count,
       la.last_seen_at
FROM licenses l
JOIN customers c ON c.id = l.customer_id
LEFT JOIN license_activations la ON la.license_id = l.id
WHERE l.status = 'ACTIVE';

-- Süresi dolmak üzere olan lisanslar (30 gün)
SELECT c.company_name, l.key, l.valid_until,
       l.valid_until - NOW() AS remaining
FROM licenses l
JOIN customers c ON c.id = l.customer_id
WHERE l.status = 'ACTIVE'
  AND l.valid_until < NOW() + INTERVAL '30 days';

Müşteri Kurulumu (On-Premise)

Müşteriye teslim edilen deployment paketi

Paket İçeriği

📄 docker-compose.yml

PostgreSQL + InfraScope App servisleri. Production-ready konfigürasyon, health check'ler, volume mount'lar dahil.

⚙️ .env.example

Konfigürasyon şablonu. LICENSE_KEY, DATABASE_URL, NEXTAUTH_SECRET ve diğer ayarlar.

🚀 install.sh

İnteraktif kurulum scripti. Prerequisite kontrolü, lisans girişi, Docker image pull.

🔄 update.sh

Güvenli güncelleme. Otomatik DB backup, migration, health check, rollback desteği.

Kurulum Adımları

Paketi İndirin

Müşteriye gönderilen zip dosyasını açın:

Terminal 
unzip infrascope-deploy-v1.0.zip
cd infrascope-deploy

Kurulum Scriptini Çalıştırın

İnteraktif installer gerekli tüm adımları otomatik yapar:

Terminal 
chmod +x install.sh
./install.sh
📋
Script sırasıyla:
  • Docker & Docker Compose kontrolü
  • Dizin yapısı oluşturma (data/, logs/)
  • .env dosyası oluşturma
  • Lisans anahtarını sorma
  • Rastgele NEXTAUTH_SECRET üretme
  • Docker image'ları çekme
  • Servisleri başlatma

Lisans Aktivasyonu (Otomatik)

İlk başlatmada uygulama otomatik olarak lisansı aktive eder:

App Başlatılır → LICENSE_KEY okunur → Machine ID üretilir → POST /activate → JWT Token alınır

Lisans Yaşam Döngüsü

Aktivasyon, doğrulama ve offline senaryolar

✓ Normal Çalışma

  • Her 24 saatte bir lisans doğrulama
  • Her 6-12 saatte bir heartbeat (kullanım raporu)
  • Cihaz/kullanıcı sayısı otomatik raporlanır
  • Limit yaklaşınca uyarı üretilir

⚠ Grace Period (7 gün)

  • İnternet kesildiğinde devreye girer
  • .license-cache dosyasındaki token kullanılır
  • Uygulama normal çalışır
  • UI'da uyarı gösterilir

✗ Restricted Mode

  • 7 gün sonra internet hâlâ yoksa
  • Uygulama read-only moda geçer
  • Yeni cihaz/ekleme yapılamaz
  • İnternet gelince otomatik toparlar
🔑
Machine ID: Aktivasyon sırasında donanım fingerprint'i üretilir. Docker container'da /app/.machine-id dosyasında saklanır. Bu dosya silinirse yeniden aktivasyon gerekir.

Güncelleme Süreci

Yeni versiyon kurulumu ve rollback
Güncelleme Komutu 
# Belirli bir versiyona güncelle
./update.sh 2.1.0

# En son versiyona güncelle
./update.sh latest
🛡️
Güvenli Güncelleme: Script otomatik olarak database backup alır. Sorun olursa ./backups/infrascope_YYYYMMDD_HHMMSS.sql dosyasından geri yükleme yapılabilir.
Rollback (Geri Yükleme) 
# Yedekten geri yükle
docker exec -i infrascope-postgres \
  psql -U infrascope infrascope \
  < ./backups/infrascope_20260217_143000.sql

Kullanışlı Komutlar

Müşteri tarafı günlük yönetim komutları

📊 Durum Kontrolü

docker compose ps
docker compose logs --tail=50 app
curl http://localhost:3000/api/health/ready

🔄 Yeniden Başlatma

docker compose restart
# veya sadece app
docker compose restart app

⬆️ Güncelleme

./update.sh 2.1.0
# veya
./update.sh latest

💾 Yedekleme

docker exec infrascope-postgres \
  pg_dump -U infrascope infrascope \
  > backup_$(date +%Y%m%d).sql

🔑 Lisans Durumu

curl http://localhost:3000/api/license/status
# veya tarayıcıda:
# http://localhost:3000/settings/license

⏹️ Durdurma

docker compose down
# Verileri de sil (dikkatli!)
docker compose down -v

Sistem Gereksinimleri

Müşteri sunucusunda gerekli minimum özellikler

🖥️ Donanım

  • CPU: 2+ çekirdek
  • RAM: 4 GB minimum (8 GB önerilen)
  • Disk: 20 GB minimum (SSD önerilen)
  • Network: 100 Mbps

💻 Yazılım

  • OS: Ubuntu 20.04+, CentOS 8+, Debian 11+
  • Docker: 24.0+
  • Docker Compose: v2.20+
  • İnternet: Lisans doğrulama için (7 gün offline destek)

🌐 Port'lar

  • 3000: Web arayüzü (HTTPS önerilen)
  • 5432: PostgreSQL (sadece internal)
  • 161/UDP: SNMP (izlenen cihazlara)
  • 22/TCP: SSH (izlenen cihazlara)
